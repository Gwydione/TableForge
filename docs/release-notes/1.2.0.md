# Gidubba 1.2.0 (formerly TableForge)

**Formerly TableForge.** **TableForge has been renamed Gidubba** (RPG Rollable Tables, by RPG Frequencies). This is
the first release under the new name. It is the same application, from the same developer and the same GitHub
project, not a new or separate one.

**Already using TableForge? Install Gidubba 1.2.0 over it. You do not need to uninstall TableForge first.** The
installer upgrades TableForge in place, and **your existing tables, collections and settings are preserved**.

Gidubba has a new name and a new icon (a Sumerian clay tablet and reed stylus), but its core functionality is
unchanged: rolling, Paste Table, Collections, exports, dddice and the Streaming Overlay all work exactly as in
TableForge 1.1.0.

## Highlights

- **New name and icon.** The window title, About, messages, tooltips, the installer, the Start Menu shortcut,
  Settings → Apps and the program's Windows file properties now say Gidubba, with the clay-tablet icon.
- **Upgrading from TableForge is in place.** The Gidubba installer recognises an installed TableForge and replaces it:
  - Settings → Apps still has **one** entry, now named **Gidubba**.
  - The **TableForge** Start Menu shortcut is replaced by a **Gidubba** one.
  - The program stays in the same folder (`%LOCALAPPDATA%\Programs\TableForge`) and is still called `TableForge.exe`,
    so a taskbar pin keeps working (it keeps the label you pinned it with; pin Gidubba again to rename it).
- **Your data does not move.** It stays in `%LOCALAPPDATA%\TableForge`, with the same files: tables, collections, recent
  rolls, settings, the dice choice, a connected dddice account and the Streaming Overlay (an OBS Local file source keeps
  working unchanged).
- **dddice:** new dddice rooms are named "Gidubba". A room that TableForge already made for your connected account keeps
  its name "TableForge" and keeps working.
- **Files are unchanged:** Collection files are still `.tfcollection` in the same format, so TableForge 1.1.0 and
  Gidubba 1.2.0 read each other's files. PUM Companion, Foundry, Tables+ and Sojour exports are the same as in 1.1.0.
- **The data format does not change** (still database schema version 10). See Data and Upgrades.

## Installation

1. Download `Gidubba-1.2.0-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If TableForge 1.1.0 or 1.0.0 is installed, leave it installed: Gidubba replaces it in place and your data is kept.
3. Start **Gidubba** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

Gidubba is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\Gidubba-1.2.0-Setup.exe` in PowerShell.

Also attached: `Gidubba-1.2.0-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`; it uses the same data folder.

## What's Included

- The new name and icon.
- Everything in TableForge 1.1.0:
  - PUM Companion export (`.pumb`): one table or a whole Collection, reviewed before saving.
  - Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
  - Table descriptions, and bold and italic result text.
  - Ranges: `96-00`, negative numbers and open-ended ranges.
  - Collections, folders, search, recent tables and recent rolls.
  - Export, Import and Delete Collection (`.tfcollection`).
  - Dice: `NdM` with a modifier, `d66` and `d100`; the situational modifier, clamp to range, inline dice, several rolls
    at once and linked tables.
  - Streaming Overlay for OBS.
  - Copy Table Text (both forms) and Copy for Sojour.
  - Foundry VTT and Owlbear Rodeo (Tables+) export.
  - Optional dddice dice.
  - Open Data Folder and About.

## Known Issues

- Some technical names still say TableForge, on purpose, so that existing installations, data and files keep working:
  the program file `TableForge.exe`, its install folder, the data folder `%LOCALAPPDATA%\TableForge`, the database file
  `tableforge.db`, the `.tfcollection` file type and the GitHub project address.
- A taskbar pin made for TableForge keeps the name it was pinned with until you pin Gidubba again.
- The icon is a square tile on a dark background, so it shows as a dark square on light Start Menu and taskbar themes.
- Unchanged from 1.1.0:
  - PUM Companion export: **Not checked in PUM Companion:** rows beyond the dice, reached only through PUM's own roll
    overrides. Not exported: table descriptions. Links are text only, and inline dice are not rolled by PUM.
  - **Questline import has not been verified.**
  - Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry
    does not reproduce Clamp.
  - Tables+ export: **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables; this is not full
    Tables+ compatibility. Several dice with a modifier (`2d6+1`) are refused.
  - Copy for Sojour was tested by pasting with Ctrl+V only.
  - Import Collection always adds a new collection, and Delete Collection cannot be undone.
  - Image-only or scanned PDFs need OCR first, and unusual PDF layouts may need manual cleanup.
  - dddice needs internet and WebView2.
  - Windows x64 only. Only one copy of Gidubba should be open at a time. Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it); the folder keeps its
TableForge name. Installing Gidubba over TableForge keeps them; uninstalling Gidubba does **not** delete them, and
reinstalling finds them again. To back up, close Gidubba and copy that folder.

1.2.0 **does not change the data format** (it stays at version 10) or the `.tfcollection` format. Updating from 1.1.0 or
1.0.0 needs no conversion and makes no safety copy, and **TableForge 1.1.0 can still open data that Gidubba 1.2.0 has used**.

Updating from an rc release older than 1.0.0 works as described in the 1.0.0 release notes.
