# Gidubba 1.3.0

Gidubba 1.3.0 adds **Auto-follow linked tables** and **Manual-selection tables**, and an optional way to make PUM
Companion roll linked tables for you. Everything else works exactly as in 1.2.0.

> **This version updates your data, and 1.2.0 cannot open it afterwards.**
> The first time Gidubba 1.3.0 starts, it updates your database from version 10 to version 11. Before changing anything,
> it saves a copy of your database as `tableforge.pre-v11-from-v10.backup.db` in your data folder. It updates nothing if
> it cannot make that copy. After the update, **Gidubba 1.2.0 (and TableForge) will refuse to open your data** until you
> restore that copy. Going back loses anything you changed after updating. See Data and Upgrades.

## Highlights

- New: **Auto-follow linked tables** (on the Roll screen, **off by default**). Turned on, a result that links to another
  table opens that table and rolls it, and so on down the chain:
  - Each table it opens says where it came from ("Auto-followed from Area Type (5)"). Every roll is an ordinary roll in
    Recent rolls and on the Streaming Overlay.
  - It follows one link at a time. A result with more than one link, or several rolls at once, follows nothing and says
    why; the **Open …** buttons are still there.
  - It stops by itself after 8 linked tables, or when one table has already been rolled automatically twice (a "reroll on
    this table" row). The link to continue by hand is still there.
  - **Stop** ends a chain, and also cancels a dddice roll in the air. Leaving the table also ends it.
  - Gidubba remembers the setting between sessions. Turned off, Gidubba behaves exactly as 1.2.0 did.
- New: **Manual-selection tables.** A table whose result you choose rather than roll, such as a "current depth" selector:
  - Mark it in Edit table: **Manual-selection table**, under Clamp to Range.
  - Auto-follow opens it **without rolling it** and waits. Type your choice and **Resolve**, and the chain continues from
    there. Pressing **Roll** on it still works, and then nothing is followed.
  - **Every existing table starts as an ordinary table (Manual-selection off).** Gidubba never guesses which tables are
    selectors: if your collections have selector tables, mark them yourself before using auto-follow.
  - Collection files (`.tfcollection`) keep the setting. Gidubba 1.2.0 can still import them, and ignores the setting.
- New, optional: **Roll linked tables automatically in PUM ({{…}})**, a checkbox in the **Export to PUM Companion…**
  review.
  - It is **unticked every time the review opens**. Unticked, the export is exactly the same as in 1.2.0, byte for byte.
  - Ticked, a link to another table in the same bundle becomes a nested roll that PUM makes itself:
    `→ Exceptional Treasure Table:` followed by a rolled treasure. The result's own text is kept as it is.
  - A link stays a `→ Table name` text line when PUM can't roll it safely. The review shows how many links will roll
    ("55 of 131 links will roll their table in PUM. 76 stay text"), and the report says why each other link stays text:
    - the link goes to, or comes from, a Manual-selection table (PUM can only roll a table, not let you choose its row);
    - the link leads back round to its own table (PUM would keep rolling round the loop);
    - another of your collections has a table with the same name (PUM finds tables by name alone, in every category,
      ignoring case, so in PUM they would be one table);
    - the table isn't in the bundle, or its name contains characters PUM uses for commands.
  - Exporting a single table (Roll screen → **Export…**) has no such option.
- **The installer, the program's folder and your data folder are unchanged.** Installing 1.3.0 over Gidubba 1.2.0 (or
  TableForge) replaces it in place, and uninstalling still leaves your data where it is.
- **The data format changes** (database schema version 10 to 11). See Data and Upgrades.

## Installation

1. **Back up first** (recommended): close Gidubba, then copy the whole `%LOCALAPPDATA%\TableForge` folder somewhere safe.
2. Download `Gidubba-1.3.0-Setup.exe` below.
3. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If Gidubba 1.2.0 (or TableForge) is installed, leave it installed: 1.3.0 replaces it in place.
4. Start **Gidubba** from the Start Menu. The first start updates your data (see above).
5. If you have selector tables (tables you pick a row from rather than roll), open each one with Edit table, tick
   **Manual-selection table** and **Save Table** before turning on **Auto-follow linked tables**.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

Gidubba is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\Gidubba-1.3.0-Setup.exe` in PowerShell.

Also attached: `Gidubba-1.3.0-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`. It uses the same data folder, so it updates your data the same way.

## Known Issues

- **Data updated by 1.3.0 cannot be opened by 1.2.0** (see Data and Upgrades).
- Auto-follow follows one link per result, and no further than 8 tables in one chain. It never chooses for you on a
  Manual-selection table.
- PUM nested rolls:
  - **Checked in PUM Companion** (Windows and iPad) with Under the Fourth Kingdom and with test bundles: nested rolls,
    names ignoring case, em dashes and ` (2)` names, and five levels of nesting.
  - PUM keeps one table per name across all its categories. A table imported with a name PUM already has replaces that
    table's rows. Gidubba keeps a link as text when another of your collections uses the same name, but it cannot see
    tables you made in PUM itself or imported from elsewhere.
  - A nested roll in PUM rolls the linked table once, even if the result's text says "roll twice".
- Unchanged from 1.2.0:
  - Some technical names still say TableForge, on purpose, so that existing installations, data and files keep working:
    the program file `TableForge.exe`, its install folder, the data folder `%LOCALAPPDATA%\TableForge`, the database
    file `tableforge.db`, the `.tfcollection` file type and the GitHub project address.
  - PUM Companion export: **Not checked in PUM Companion:** rows beyond the dice, reached only through PUM's own roll
    overrides. Not exported: table descriptions. Inline dice are not rolled by PUM.
  - **Questline import has not been verified.**
  - Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry
    does not reproduce Clamp.
  - Tables+ export: **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables; this is not full
    Tables+ compatibility. Several dice with a modifier (`2d6+1`) are refused.
  - Copy for Sojour was tested by pasting with Ctrl+V only.
  - Import Collection always adds a new collection, and Delete Collection cannot be undone.
  - Image-only or scanned PDFs need OCR first, and unusual PDF layouts may need manual cleanup.
  - dddice needs internet and WebView2.
  - Windows x64 only. Only one copy of Gidubba should be open at a time. Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing 1.3.0 over
1.2.0 keeps them, uninstalling Gidubba does **not** delete them, and reinstalling finds them again. To back up, close
Gidubba and copy that folder.

**1.3.0 changes the data format (database schema version 10 to 11).** It adds one setting to every table, Manual-selection,
which starts **off** for all of them, so every existing table, link and roll behaves exactly as before.

- **The automatic safety copy:** before updating, Gidubba saves `tableforge.pre-v11-from-v10.backup.db` beside
  `tableforge.db`, and updates nothing if it cannot. If the update itself fails, Gidubba says so and where the copy is.
- **Going back to 1.2.0:** 1.2.0 refuses data that 1.3.0 has updated ("made by a newer version") and changes nothing.
  To go back, close Gidubba, reinstall 1.2.0 and put the backup copy in place of `tableforge.db`. **Anything changed after
  the update is lost.** Use Export Collection first to keep it: 1.2.0 imports those files.
- **Settings:** the auto-follow setting is kept in a new small file, `auto-follow.txt`, in the same folder.
- **Collection files:** `.tfcollection` keeps its format version. A Manual-selection table is saved with that setting;
  Gidubba 1.2.0 imports such a file and ignores the setting.

Updating straight from TableForge 1.1.0 or 1.0.0 works the same way, and also applies the 1.2.0 rename (see the 1.2.0
release notes). Updating from an rc release older than 1.0.0 works as described in the 1.0.0 release notes.
