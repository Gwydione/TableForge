# TableForge 1.1.0

TableForge 1.1.0 adds **PUM Companion export**: save one table, or a whole Collection, as a `.pumb` bundle that PUM
Companion imports. Everything else works exactly as in 1.0.0.

## Highlights

- New: **PUM Companion export**.
  - **Collection:** choose **Export to PUM Companion…** under Export Collection / Delete Collection.
  - **Table:** on the Roll screen, choose **Export…** → **Save PUM Companion Bundle…** for the table shown.
  - In PUM Companion, import the `.pumb` file with PUM's own import.
- **A review before saving.** It shows how many tables will be exported and how many skipped, with the reason for each
  skipped table, any warnings and the full report. **Copy Report** copies the report.
  - **Save Bundle…** then asks where to save the file.
  - Cancelling at either step saves nothing.
  - The file is written completely or not at all: an existing file is never left half-replaced.
- **Rolls show the same result.** For every roll of a table's own dice, an exported table shows in PUM what it shows in
  TableForge.
  - TableForge checks every table before exporting it.
  - A table it can't reproduce exactly is skipped, with the reason and an example roll.
  - Skipped: overlapping rows; dice that can roll below 1 where PUM's "below 1 counts as 1" would change the result; text
    that PUM would run as a command.
- **No Match stays no result.** Where no row covers a roll (a gap, or the low rolls of `d6-2`), the PUM table has a
  `(No result)` row, and its last row catches any higher roll. **Clamp to Range** is kept.
- **Several result sets become one PUM table.** Each result lists every set (`Weather: Rain` / `Wind: Calm`), so one roll
  still gives all of them.
- **Dice and ranges:** `1d6`, `2d6+1` and `1d20-2` are written as they are; a `d66` becomes PUM's `1D66`. `96-00` on a `d100` and open-ended rows (`26+`) work.
- **Links** become a text line under the result, `→ Table name`, adding "(not included in this export)" when that table
  isn't in the bundle. PUM doesn't open or roll the linked table.
- **Text:** bold and italic become PUM's Markdown. Inline dice such as `1d6` stay as text.
- **Blank results:** a row with no text exports blank, with a warning. A table whose every result is blank is skipped.
- **Names and categories:**
  - Names are made safe for PUM (`/` becomes ` - `), and repeated names get ` (2)`.
  - Each table's PUM category is the collection's name, or `Collection - Folder`.
  - Exporting the same table again (same collection, folder and name) gives the same PUM table.
- **Importing a bundle again:** PUM Companion offers to overwrite tables it already has, and overwriting replaces them,
  including any changes made to them in PUM. The review says so whenever there is a bundle to save.
- **Existing exports are unchanged**, and so is rolling.
- **The data format does not change** (still database schema version 10, and `.tfcollection` is unchanged). See Data and
  Upgrades.

## Installation

1. Download `TableForge-1.1.0-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If 1.0.0 is installed, it is replaced in place and your data is kept.
3. Start **TableForge** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

TableForge is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\TableForge-1.1.0-Setup.exe` in PowerShell.

Also attached: `TableForge-1.1.0-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`; it uses the same data folder.

## What's Included

- PUM Companion export (`.pumb`): one table or a whole Collection, reviewed before saving.
- Everything in 1.0.0:
  - Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
  - Table descriptions, and bold and italic result text.
  - Ranges: `96-00`, negative numbers and open-ended ranges.
  - Collections, folders, search, recent tables and recent rolls.
  - Export, Import and Delete Collection (`.tfcollection`).
  - Dice: `NdM` with a modifier, `d66` and `d100`; the situational modifier, clamp to range, inline dice, several rolls
    at once and linked tables.
  - Streaming Overlay for OBS.
  - Copy Table Text (both forms) and Copy for Sojour.
  - Foundry VTT and Owlbear Rodeo (Tables+) export.
  - Optional dddice dice.
  - Open Data Folder and About.

## Known Issues

- PUM Companion export:
  - **Checked in PUM Companion:** imports of TableForge-made bundles of a single table and of whole Collections, rolled
    there with the expected results:
    - gaps, Clamp to Range, modifiers;
    - `d66`, a real `1d66`, `d100` with `00`, open-ended rows;
    - several result sets, links (including unresolved ones), bold and italic, empty rows;
    - special and repeated names, categories and folders;
    - importing the same bundle again (PUM offers to overwrite).
  - **Not checked there:** rows beyond the dice, reached only through PUM's own roll overrides.
  - Not exported: table descriptions, and Fantasy Grounds or other formats. Links are text only, and inline dice are not
    rolled by PUM.
- Unchanged from 1.0.0:
  - **Questline import has not been verified.**
  - Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry
    does not reproduce Clamp.
  - Tables+ export: **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables; this is not full
    Tables+ compatibility. Still untested there: negative modifiers and negative ranges, gaps and overlaps, `{2d6}` and
    `#reroll` in results, a real `1d66`, `d100`, and importing a saved file. Several dice with a modifier (`2d6+1`) are refused.
  - Copy for Sojour was tested by pasting with Ctrl+V only.
  - Import Collection always adds a new collection, and Delete Collection cannot be undone.
  - Image-only or scanned PDFs need OCR first, and unusual PDF layouts may need manual cleanup.
  - dddice needs internet and WebView2.
  - Windows x64 only. Only one copy of TableForge should be open at a time. Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing a newer version
keeps them; uninstalling TableForge does **not** delete them, and reinstalling finds them again. To back up, close
TableForge and copy that folder.

1.1.0 **does not change the data format** (it stays at version 10) or the `.tfcollection` format. Updating from 1.0.0
needs no conversion and makes no safety copy, and **1.0.0 can still open data that 1.1.0 has used**. PUM export only reads
your tables: it never changes them, and it writes nothing except the `.pumb` file you choose.

Updating from an rc release older than 1.0.0 works as described in the 1.0.0 release notes.
