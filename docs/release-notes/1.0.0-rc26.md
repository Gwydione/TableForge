# TableForge 1.0.0-rc26

Release candidate for external testing. TableForge turns random tables from RPG books and PDFs into fast, searchable,
rollable digital tables.

## Highlights

- New: **Table Description**. A table can have an optional plain-text description, such as "Roll when entering a new
  region or when the weather changes." Type it in the **Description** box when you review or edit the table (up to
  2,000 characters, line breaks allowed). While rolling, it appears under the table's dice; a followed table shows its
  own. A table without a description shows nothing extra on the Roll screen. A description is only a note: it never
  changes how the table rolls, and it is not shown in the table list, Recent tables or Recent rolls.
- **Descriptions travel in Portable Collections.** A collection with no descriptions is still saved in the rc25 file
  format (format version 1), so rc25 can import it. A collection with any table description is saved as format
  version 2, which rc25 refuses ("uses a newer file format… Nothing was changed") instead of importing it without its
  descriptions. rc26 imports both.
- Improved: **Situational modifier entry**. Moving into the **Modifier** box with Tab, Shift+Tab or a click now selects
  its value, so typing `+2` replaces the `0` instead of making `+20`. After a roll resets the box to `0`, the next
  modifier you type replaces it too. How the modifier works is unchanged.
- **Existing exports are unchanged**: Copy Table Text (and Spaces), Copy for Sojour, Foundry JSON and Tables+ JSON give
  exactly the same output as before and never include the description.
- **The data format changes** (database schema version 10). Updating makes a safety copy first; afterwards rc25 and
  earlier cannot open the data. See Data and Upgrades.
- From rc25: **Portable Collections** (Export / Import Collection, `.tfcollection`) and **Delete Collection…**. From
  rc24: **Bold and italic result text**. From rc23: **Open-ended ranges** (`26+`, `1 or less`) and rows beyond the dice;
  Foundry and Tables+ refuse open-ended ranges. From rc22: **Copy Table Text (Spaces)**.
  **Questline import has not been verified.**
- From rc21: **Owlbear Rodeo (Tables+) export**. From rc20: **Copy for Sojour**. From rc19: **Foundry VTT export**.
- Everything from rc18: paste a table from a PDF or book, review and correct it, save it, find it and roll it; Built-in or
  dddice dice; linked tables, inline dice, several rolls at once.

## Installation

1. Download `TableForge-1.0.0-rc26-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
3. Start **TableForge** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

This release candidate is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt`:
`Get-FileHash .\TableForge-1.0.0-rc26-Setup.exe` in PowerShell.

Also attached: `TableForge-1.0.0-rc26-win-x64.zip`, the same program without an installer (extract it and run
`TableForge.exe`; it uses the same data folder).

## What's Included

- Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
- Optional plain-text table descriptions, shown while rolling.
- Bold and italic in result text, shown when rolled.
- Ranges: single numbers, spans (`5-8`), `96-00` and `08` on a `d100`, negative numbers, and open-ended `26+` /
  `20 or more` / `1 or less`.
- Collections, folders, search, recent tables and recent rolls.
- Export Collection, Import Collection (`.tfcollection`) and Delete Collection.
- Dice: `NdM` with an optional modifier (`2d6+1`), `d66`, and `d100` with `00`.
- Situational modifier, per-table clamp to range, inline dice, several rolls at once, linked tables.
- Copy Table Text (tab-separated), Copy Table Text (Spaces) and Copy for Sojour.
- Foundry VTT export and Owlbear Rodeo (Tables+) export: one result set as import JSON, copied or saved as a `.json` file.
- Optional dddice visual dice: guest mode, or connect your dddice account (via dddice.com, never your password) and choose a
  compatible theme from your Dice Box.
- Open Data Folder, About TableForge, LICENSE / PRIVACY / THIRD-PARTY-NOTICES.

## Known Issues

- Descriptions are plain text only (no bold, italic or links), up to 2,000 characters, and are never taken from pasted
  text: type them on the Review screen. They are not included in Copy Table Text, Copy for Sojour, Foundry or Tables+
  exports.
- A `.tfcollection` file with table descriptions (format version 2) can be imported by rc26 or later only; one without
  descriptions can still be imported by rc25. Files larger than 25 MB are refused.
- Import always adds a new collection: there is no merging into, or updating of, a collection you already have, and
  importing the same file twice gives two independent copies. Collections cannot be renamed.
- A `.tfcollection` file is a way to share one collection, not a full backup: it does not include your other collections,
  recent rolls or settings. To back up everything, copy the data folder (see Data and Upgrades).
- A collection whose rows link to a table in a different collection cannot be exported (TableForge itself never creates
  such links); the refusal names the row.
- Delete Collection cannot be undone.
- Formatting is bold and italic only, on result text only (not table or result-set names). Pasting keeps text only, and
  no export to another tool carries formatting. Recent Rolls show plain text.
- Tables with hundreds of rows take a moment to open on the Review screen; formatting every row of such a table adds a
  little more.
- Image-only or scanned PDFs need OCR first; TableForge reads the text you copy.
- Unusual PDF layouts may need manual cleanup on the Review screen, and TableForge does not find tables in a whole PDF.
- A pasted line starting with a negative number is read as a row only where a row can sit (the first row, or one that
  continues upward from the row before it); elsewhere it stays part of the text above. Check such rows on the Review
  screen.
- Open-ended ranges cannot be exported to Foundry or Tables+ and are not available for `d66`.
- Copy Table Text and Copy Table Text (Spaces) are generic text, not formats for a particular VTT. Importing Copy Table
  Text (Spaces) into Questline has not been verified.
- Copy for Sojour was tested by pasting with Ctrl+V only. It copies rows, not the table's name, dice or links; line
  breaks and tabs inside a result become spaces.
- Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry does
  not reproduce Clamp. Fantasy Grounds is not supported yet.
- Tables+ export is unchanged since rc23. **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables;
  this is not full Tables+ compatibility. Still untested there: negative modifiers and negative ranges, gaps and
  overlaps, `{2d6}` and `#reroll` in results, a real `1d66`, `d100`, a TableForge export with a single-die modifier, and
  importing a file saved with **Save Tables+ JSON…**. Several dice with a modifier (`2d6+1`) are refused. Tables+ JSON
  has no Clamp setting.
- dddice needs internet and WebView2; connecting an account takes a few browser steps.
- Windows x64 only. Only one copy of TableForge should be open at a time.
- Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing a newer version
keeps them; uninstalling TableForge does **not** delete them, and reinstalling finds them again. To back up, close
TableForge and copy that folder.

rc26 **changes the data format** to version 10 to store table descriptions. Every existing table simply gets no
description; nothing else changes. The first time rc26 opens your data it saves a safety copy beside it,
`tableforge.pre-v10-from-v9.backup.db` (from rc24 or rc25), and updates nothing if that copy cannot be made. After the
update, **rc25 and earlier cannot open the data**: they say it was made by a newer version and change nothing. To go
back to rc25, close TableForge and restore that safety copy as `tableforge.db` (tables, descriptions and rolls added
since then will be lost). Updating from rc23 or earlier works the same way, with a safety copy named after the version
it came from (for example `tableforge.pre-v10-from-v8.backup.db`).
