# Gidubba 1.4.0

Gidubba 1.4.0 adds **Unique Results**: rows that can come up only once until you reset them. It also simplifies the left
side of the window, moves **Recent rolls** into a panel you can collapse, and lays out tables with several result sets in
columns that fit the window. Tables without Unique rows roll exactly as in 1.3.0.

> **This version updates your data, and 1.3.0 cannot open it afterwards.**
> The first time Gidubba 1.4.0 starts, it updates your database from version 11 to version 12. Before changing anything,
> it saves a copy of your database as `tableforge.pre-v12-from-v11.backup.db` in your data folder. It updates nothing if
> it cannot make that copy. After the update, **Gidubba 1.3.0 (and every earlier version) will refuse to open your data**.
> That backup copy is the only way back to 1.3.0, and going back loses anything you changed after updating. See Data and
> Upgrades.

## Highlights

- New: **Unique Results.** Mark any row of a table as **Unique**, and once it has been the result it is skipped until you
  reset the table. Every other row stays repeatable, as before.
  - Mark rows in Edit table: each row has a **Unique** checkbox (**Ctrl+U** in a row). **Mark All Unique** and **Clear
    Unique** change every row of the result set (of every result set, when they are shown side by side).
  - **Every existing row starts as an ordinary, repeatable row.** Nothing rolls differently until you mark rows Unique.
- **How rerolls work.** Gidubba always rolls the table's own dice. If the roll lands on a Unique row that has already been
  used, the roll is discarded and the same dice are rolled again, so every result still available keeps its usual chance.
  - The situational modifier and Clamp to Range apply to every reroll, exactly as to any roll.
  - A roll that lands where no row covers it (a gap) is "no result", as it always was; it is not rerolled.
  - When result sets or rows overlap, a roll is refused if it lands on **any** used Unique row, and an accepted roll uses
    up every Unique row it lands on.
  - Only the accepted result is shown and recorded. When rerolls were needed, the result and Recent rolls say so
    ("Rerolled 2×").
  - If every result the dice can reach has been used, nothing is rolled: "All results used — Reset to roll again."
  - Built-in dice try up to 10,000 times for one result. dddice tries **10 throws** (the first included), since every
    throw takes a few seconds. If no unused result comes up, it stops and nothing is used up, with a message saying so.
    It never switches to Built-in dice for you. **Stop** also stops a run of rerolls.
  - The same rules apply to auto-follow, several rolls at once (each result is used up before the next roll) and to a
    result you type yourself. A typed result on a used Unique row is refused: "Result already used — choose another
    result."
- New: **Used results are shown and can be reset.**
  - On the Roll screen, Unique rows are tagged **Unique**, and used ones are tagged **Used** and shown in grey. The text
    stays readable, and the green highlight on the row just rolled still shows.
  - A table with Unique rows shows how many are used ("Unique results: 3 of 8 used") and a **Reset Used Results…**
    button. Reset asks first, makes every used result of that one table available again, and does not change which
    rows are Unique.
  - Editing a row's text or range keeps whether it has been used. Deleting the row deletes its used state too.
- **dddice and Unique Results:** each throw is a real dddice roll that you see land. A throw on a used row is followed by
  another throw of the same dice, up to 10 in all.
- **The left side is simpler, and Recent rolls can be collapsed.**
  - The table list now fills the left side, under a heading that says what it shows ("All tables", a folder's tables,
    or "Search results"). The separate **Recent tables** list is gone.
  - **Recent rolls** is now a panel at the bottom of the main area, headed "Recent rolls (N)". It starts collapsed;
    click its heading to open it. Each roll shows its time, any rerolls and its whole result. Clicking one still opens its
    table. The panel is hidden while you paste or review a table.
- **Tables with several result sets fit the window better.** Their columns, on the Roll screen and in Edit table, now
  share the window's width, each at least wide enough to read, and scroll sideways when there are more than fit. The
  column headings stay lined up with their rows.
- **Collection files (`.tfcollection`) can carry Unique rows (format version 3).**
  - A collection with any Unique row is saved as format version 3. Gidubba 1.3.0 and earlier refuse such a file ("newer
    file format … Nothing was changed.") rather than import its Unique rows as ordinary rows. After exporting, the status
    line says so.
  - A collection without Unique rows is saved exactly as before, as version 1 (or version 2 with table descriptions), so
    1.3.0 still imports it.
  - Only which rows are Unique is saved, never which have been used: an imported collection starts with every result
    available. Gidubba 1.4.0 imports versions 1, 2 and 3.
- Other exports (Copy Table Text, Copy for Sojour, Foundry, Tables+ and PUM Companion) are unchanged: they export every
  row, and leave out whether rows are Unique or used.
- **The project moved on GitHub** to [github.com/Gwydione/Gidubba](https://github.com/Gwydione/Gidubba). The About
  window, the installer's links and the README now point there.
- **The installer, the program's folder and your data folder are unchanged.**
- **The data format changes** (database schema version 11 to 12). See Data and Upgrades.

## Installation

1. **Back up first** (recommended): close Gidubba, then copy the whole `%LOCALAPPDATA%\TableForge` folder somewhere safe.
2. Download `Gidubba-1.4.0-Setup.exe` below.
3. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
   If Gidubba 1.3.0 (or an earlier Gidubba or TableForge) is installed, leave it installed: 1.4.0 replaces it in place.
4. Start **Gidubba** from the Start Menu. The first start updates your data (see above).

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

Gidubba is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt` by running
`Get-FileHash .\Gidubba-1.4.0-Setup.exe` in PowerShell.

Also attached: `Gidubba-1.4.0-win-x64.zip`, the same program without an installer. Extract it and run
`TableForge.exe`. It uses the same data folder, so it updates your data the same way.

## What's Included

- Unique Results, with used-result indicators, rerolls, and **Reset Used Results…**.
- The simpler sidebar and the collapsible Recent rolls panel.
- Aligned result-set columns that fit the window.
- `.tfcollection` format version 3 for collections with Unique rows.
- Everything in Gidubba 1.3.0:
  - Auto-follow linked tables, with **Stop**, and Manual-selection tables.
  - PUM Companion export (`.pumb`), with optional native nested rolls.
  - Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
  - Table descriptions, and bold and italic result text.
  - Ranges: `96-00`, negative numbers and open-ended ranges.
  - Collections, folders, search and recent rolls.
  - Export, Import and Delete Collection (`.tfcollection`).
  - Dice: `NdM` with a modifier, `d66` and `d100`; the situational modifier, clamp to range, inline dice, several rolls
    at once and linked tables.
  - Streaming Overlay for OBS.
  - Copy Table Text (both forms) and Copy for Sojour.
  - Foundry VTT and Owlbear Rodeo (Tables+) export.
  - Optional dddice dice.
  - Open Data Folder and About.

## Known Issues

- **Data updated by 1.4.0 cannot be opened by 1.3.0** (see Data and Upgrades).
- **Collection files with Unique rows (format version 3) cannot be imported by 1.3.0 or earlier.**
- Unique Results:
  - Which results have been used is kept on this computer only. It is not in exported collection files, and there is no
    undo for a single used result: **Reset Used Results…** resets the whole table.
  - With dddice, a table with few unused results left may use all 10 throws without landing on one. Nothing is used up;
    roll again, type a result, or switch to Built-in dice, which try far more often.
  - Exports to other programs leave out Unique: PUM Companion, Foundry and Tables+ can roll a used row again.
- The **Recent tables** list is no longer shown; open tables from the list or with search.
- Unchanged from 1.3.0:
  - Some technical names still say TableForge, on purpose, so that existing installations, data and files keep working:
    the program file `TableForge.exe`, its install folder, the data folder `%LOCALAPPDATA%\TableForge`, the database
    file `tableforge.db` and the `.tfcollection` file type.
  - Auto-follow follows one link per result, and no further than 8 tables in one chain. It never chooses for you on a
    Manual-selection table.
  - PUM Companion export: **Not checked in PUM Companion:** rows beyond the dice, reached only through PUM's own roll
    overrides. Not exported: table descriptions. Inline dice are not rolled by PUM. A nested roll in PUM rolls the
    linked table once, even if the result's text says "roll twice".
  - **Questline import has not been verified.**
  - Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry
    does not reproduce Clamp.
  - Tables+ export: **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables; this is not full
    Tables+ compatibility. Several dice with a modifier (`2d6+1`) are refused.
  - Copy for Sojour was tested by pasting with Ctrl+V only.
  - Import Collection always adds a new collection, and Delete Collection cannot be undone.
  - Image-only or scanned PDFs need OCR first, and unusual PDF layouts may need manual cleanup.
  - dddice needs internet and WebView2.
  - Windows x64 only. Only one copy of Gidubba should be open at a time. Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing 1.4.0 over
1.3.0 keeps them, uninstalling Gidubba does **not** delete them, and reinstalling finds them again. To back up, close
Gidubba and copy that folder.

**1.4.0 changes the data format (database schema version 11 to 12).** It gives every row a permanent identity of its own
(so that a used result stays used however you edit the row), adds the Unique setting to every row, **off** for all of
them, adds a place to keep which results have been used (empty), and lets Recent rolls note rerolls (none for every
earlier roll). Every existing table, row, link and roll behaves exactly as before.

- **The automatic safety copy:** before updating, Gidubba saves `tableforge.pre-v12-from-v11.backup.db` beside
  `tableforge.db`, and updates nothing if it cannot. If the update itself fails, Gidubba says so and where the copy is,
  and your data is left as it was.
- **Going back to 1.3.0:** 1.3.0 refuses data that 1.4.0 has updated ("made by a newer version") and changes nothing.
  **The automatic safety copy is the only way back.** To go back, close Gidubba, reinstall 1.3.0 and put
  `tableforge.pre-v12-from-v11.backup.db` in place of `tableforge.db`. **Anything changed after the update is lost.** To
  keep new or changed tables, use Export Collection first: 1.3.0 imports a collection without Unique rows (clear them
  with **Clear Unique** before exporting). Gidubba keeps only the newest three safety copies, so keep your own copy if
  you might go back later.
- **Settings:** no new settings files. Whether Recent rolls is open is not remembered between sessions.
- **Collection files:** see Highlights. Files from any earlier version import as before.

Updating straight from Gidubba 1.2.0 or TableForge 1.1.0 or 1.0.0 works the same way: it makes one safety copy named
after the version your data had (for example `tableforge.pre-v12-from-v10.backup.db`) and also applies the earlier
updates (see the 1.3.0 and 1.2.0 release notes). Updating from an rc release older than 1.0.0 works as described in the
1.0.0 release notes.

## Feedback

Please report problems on [GitHub Issues](https://github.com/Gwydione/Gidubba/issues). Include your Gidubba version,
your Windows version, what you were doing and any error message. For Unique Results problems, say whether you used
Built-in dice or dddice. For export problems, also include the export report (**Copy Report**) where there is one.
**Never post dddice tokens or account credentials.**
