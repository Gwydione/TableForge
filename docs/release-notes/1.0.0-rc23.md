# TableForge 1.0.0-rc23

Release candidate for external testing. TableForge turns random tables from RPG books and PDFs into fast, searchable,
rollable digital tables.

## Highlights

- New: **Open-ended ranges**. A row's range can be `26+`, `20 or more` (no upper bound) or `1 or less` (no lower bound),
  when pasting a table or editing it on the Review screen. The row keeps the range as written everywhere TableForge shows
  it, and a roll resolves to it however far past its bound it lands. Open-ended ranges are not available for `d66`
  tables.
- New: **Rows beyond the dice** (tables for modified rolls). Any table can now have rows the dice alone never reach, such
  as `-10-0` on a `d20`, including a leading real minus sign (`−10–0`). Before, negative ranges were only accepted for dice
  that could roll them. For example, this `d20` table now pastes as seven rows and rolls as written:

  ```
  -10-0 The character is dead.
  1-5 ...
  21-25 The character was simply knocked out...
  26+ The character recovers immediately, ready to fight.
  ```

- **Review notes for such tables:** when a result set covers every number its dice can roll, its rows beyond them are
  taken as written for modified rolls and shown as information ("outside the natural d20 range (1–20); only a modified
  roll reaches it"), not as a warning. Gaps are then also looked for between those rows (`21-25` then `27+` reports 26).
  A result set that leaves part of its dice uncovered still gets the usual warnings.
- **Rolling:** a situational or stored modifier that pushes a roll past the dice lands on the matching row (`d20` 7 with
  -10 is -3, which finds the `-10-0` row). A roll typed by hand may be any number one of the table's rows covers.
- **Clamp to table range** clamps to a table's lowest and highest rows as before; an open-ended side is never clamped,
  because nothing lies beyond it.
- **Foundry and Tables+ refuse open-ended ranges**: their ranges are two numbers, and TableForge will not invent one, so
  **Export…** says the table contains an open-ended range and exports nothing. Rows beyond the dice with ordinary numbers
  (`-10-0` on a `d20`) export as they are. Copy Table Text, Copy Table Text (Spaces) and Copy for Sojour keep the range as
  written (`26+`).
- **The data format changes (version 8)** so that open-ended rows can be stored. See Data and Upgrades.
- From rc22: **Copy Table Text (Spaces)**. **Questline import has not been verified.**
- From rc21: **Owlbear Rodeo (Tables+) export**. From rc20: **Copy for Sojour**. From rc19: **Foundry VTT export**.
- Everything from rc18: paste a table from a PDF or book, review and correct it, save it, find it and roll it; Built-in or
  dddice dice; linked tables, inline dice, several rolls at once.

## Installation

1. Download `TableForge-1.0.0-rc23-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
3. Start **TableForge** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work.

This release candidate is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt`:
`Get-FileHash .\TableForge-1.0.0-rc23-Setup.exe` in PowerShell.

Also attached: `TableForge-1.0.0-rc23-win-x64.zip`, the same program without an installer (extract it and run
`TableForge.exe`; it uses the same data folder).

## What's Included

- Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
- Ranges: single numbers, spans (`5-8`), `96-00` and `08` on a `d100`, negative numbers, and open-ended `26+` /
  `20 or more` / `1 or less`.
- Collections, folders, search, recent tables and recent rolls.
- Dice: `NdM` with an optional modifier (`2d6+1`), `d66`, and `d100` with `00`.
- Situational modifier, per-table clamp to range, inline dice, several rolls at once, linked tables.
- Copy Table Text (tab-separated), Copy Table Text (Spaces) and Copy for Sojour.
- Foundry VTT export and Owlbear Rodeo (Tables+) export: one result set as import JSON, copied or saved as a `.json` file.
- Optional dddice visual dice: guest mode, or connect your dddice account (via dddice.com, never your password) and choose a
  compatible theme from your Dice Box.
- Open Data Folder, About TableForge, LICENSE / PRIVACY / THIRD-PARTY-NOTICES.

## Known Issues

- Image-only or scanned PDFs need OCR first; TableForge reads the text you copy.
- Unusual PDF layouts may need manual cleanup on the Review screen, and TableForge does not find tables in a whole PDF.
- A pasted line starting with a negative number is read as a row only where a row can sit (the first row, or one that
  continues upward from the row before it); elsewhere it stays part of the text above, so a wrapped "-5 to hit" is not
  split off. Check such rows on the Review screen.
- Open-ended ranges cannot be exported to Foundry or Tables+ (see Highlights) and are not available for `d66`.
- Copy Table Text and Copy Table Text (Spaces) are generic text, not formats for a particular VTT. Importing Copy Table
  Text (Spaces) into Questline has not been verified.
- Copy for Sojour was tested by pasting with Ctrl+V only. It copies rows, not the table's name, dice or links; line
  breaks and tabs inside a result become spaces.
- Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry does
  not reproduce Clamp. Fantasy Grounds is not supported yet.
- Tables+ export is unchanged since rc21 apart from refusing open-ended ranges. **Checked in Tables+:** only `d20`, `d66`
  (`T66`) and unmodified `2d6` tables; this is not full Tables+ compatibility. Still untested there: negative modifiers
  and negative ranges, gaps and overlaps, `{2d6}` and `#reroll` in results, a real `1d66`, `d100`, a TableForge export
  with a single-die modifier, and importing a file saved with **Save Tables+ JSON…**. Several dice with a modifier
  (`2d6+1`) are refused. Tables+ JSON has no Clamp setting.
- dddice needs internet and WebView2; connecting an account takes a few browser steps.
- Windows x64 only. Only one copy of TableForge should be open at a time.
- Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing a newer version
keeps them; uninstalling TableForge does **not** delete them, and reinstalling finds them again. To back up, close
TableForge and copy that folder.

rc23 updates the data format from version 7 to version 8. Existing tables are unchanged. Before updating, it makes an
automatic safety copy, `tableforge.pre-v8-from-v7.backup.db`, in the data folder. After the update, **rc22 and earlier
cannot open the data**: they say it was made by a newer version. To go back to an older release candidate, close
TableForge and restore that safety copy as `tableforge.db` (tables and rolls added since then will be lost).
