# TableForge 1.0.0

The first stable release of TableForge. TableForge turns random tables from RPG books and PDFs into fast, searchable,
rollable digital tables: **Paste → Review/Correct → Save → Find → Roll → Read**.

## Highlights

- New since rc26: **Streaming Overlay (OBS)**. Show the latest TableForge result (table name, roll value and result text)
  in OBS as its own Browser Source, on a transparent background; OBS decides where it goes and how big it is. Choose
  **Streaming Overlay…** at the bottom of the window, tick **Enable streaming overlay**, and add the generated
  `streaming-overlay.html` (**Copy** gives its path) to OBS as a Browser Source with **Local file** ticked. Loaded that
  way it starts showing results by itself whenever TableForge is running, even if OBS was opened first.
- **Show table name** and **Show roll value** can be turned off; the result text is always shown, with its bold and
  italic. **Show Test Result** lets you place it without rolling and **Clear Overlay** empties it; neither is a roll or
  appears in Recent rolls.
- **It follows your rolls exactly**: Built-in dice, dddice and rolls you type yourself all update it. The latest result
  stays until another replaces it or you clear it; opening other tables or following a link never changes it, but rolling
  the linked table does. With a situational modifier it shows the final number only (the arithmetic stays on the Roll
  screen); with Clamp it shows the number actually rolled; a roll no row covers shows "No entry covers N." in place of the
  previous result. Rolling inline dice in the current result ("2d6 Skeletons") updates it in place ("7 Skeletons").
- **No stale results**: when TableForge closes, the overlay goes blank within a few seconds.
- **dddice's 3D dice as a separate OBS source**: with a connected dddice account, **Open my dddice room** opens your
  TableForge room on dddice.com, where **Streaming tools** gives the 3D Dice link to add to OBS as a second Browser Source.
  dddice draws the dice (their look and size are set in dddice); TableForge never sees or stores that link. If TableForge
  says "dddice room changed. Your OBS dice source may need to be updated.", replace that source's link.
- **Local only**: the overlay is off by default and, while on, is reachable only from this computer (`127.0.0.1`), on port
  **41285** unless you choose another in the dialog. TableForge never switches ports by itself.
- **Existing exports are unchanged**, and nothing about rolling changes when the overlay is off.
- **The data format does not change** (still database schema version 10): rc26 and 1.0.0 use the same database. See Data
  and Upgrades.
- Also in 1.0.0, from the rc test releases: **Table Description**; **Portable Collections** (Export / Import Collection,
  `.tfcollection`) and **Delete Collection…**; **Bold and italic result text**; **Open-ended ranges** (`26+`, `1 or less`)
  and rows beyond the dice (Foundry and Tables+ refuse open-ended ranges); Copy Table Text (Spaces); **Owlbear Rodeo
  (Tables+) export**; Copy for Sojour; Foundry VTT export. **Questline import has not been verified.**
- And the core of TableForge: paste a table from a PDF or book, review and correct it, save it, find it and roll it;
  Built-in or dddice dice; linked tables, inline dice, several rolls at once.

## Installation

1. Download `TableForge-1.0.0-Setup.exe` below.
2. Run it. It installs for your Windows user only, with no administrator prompt, into `%LOCALAPPDATA%\Programs\TableForge`.
3. Start **TableForge** from the Start Menu.

Requires 64-bit Windows 10 or 11. .NET is included. The Microsoft Edge WebView2 Runtime (part of Windows 11 and current
Windows 10) is needed only for dddice dice; Built-in dice always work. The Streaming Overlay needs OBS Studio (or another
program with a browser source) on the same computer.

TableForge is **not code-signed**, so Windows SmartScreen may warn about it. If you trust this download, choose
**More info** → **Run anyway**. Check the file against `SHA256SUMS.txt`:
`Get-FileHash .\TableForge-1.0.0-Setup.exe` in PowerShell.

Also attached: `TableForge-1.0.0-win-x64.zip`, the same program without an installer (extract it and run
`TableForge.exe`; it uses the same data folder).

## What's Included

- Paste Table with a conservative parser and a Review/Correct screen (PDF clean-up tools, multi-column result sets).
- Optional plain-text table descriptions, shown while rolling.
- Bold and italic in result text, shown when rolled.
- Ranges: single numbers, spans (`5-8`), `96-00` and `08` on a `d100`, negative numbers, and open-ended `26+` /
  `20 or more` / `1 or less`.
- Collections, folders, search, recent tables and recent rolls.
- Export Collection, Import Collection (`.tfcollection`) and Delete Collection.
- Dice: `NdM` with an optional modifier (`2d6+1`), `d66`, and `d100` with `00`.
- Situational modifier, per-table clamp to range, inline dice, several rolls at once, linked tables.
- Streaming Overlay for OBS (local file or `127.0.0.1` URL), with Show Test Result and Clear Overlay.
- Copy Table Text (tab-separated), Copy Table Text (Spaces) and Copy for Sojour.
- Foundry VTT export and Owlbear Rodeo (Tables+) export: one result set as import JSON, copied or saved as a `.json` file.
- Optional dddice visual dice: guest mode, or connect your dddice account (via dddice.com, never your password) and choose a
  compatible theme from your Dice Box.
- Open Data Folder, About TableForge, LICENSE / PRIVACY / THIRD-PARTY-NOTICES.

## Known Issues

- The Streaming Overlay shows one result: the latest. A URL Browser Source (instead of the recommended local file) must be
  refreshed in OBS if OBS was started before TableForge, and after changing the overlay's port the OBS source needs one
  refresh. Two copies of TableForge cannot use the same port; the dialog says so.
- dddice's 3D dice can be shown in OBS only with a connected dddice account (not with guest dice), using dddice's own
  Streaming tools link. If dddice gives the account a new room, that link must be replaced.
- Descriptions are plain text only (no bold, italic or links), up to 2,000 characters, and are never taken from pasted
  text: type them on the Review screen. They are not included in Copy Table Text, Copy for Sojour, Foundry or Tables+
  exports.
- A `.tfcollection` file with table descriptions (format version 2) can be imported by rc26 or later only; one without
  descriptions can still be imported by rc25. Files larger than 25 MB are refused.
- Import always adds a new collection: there is no merging into, or updating of, a collection you already have, and
  importing the same file twice gives two independent copies. Collections cannot be renamed.
- A `.tfcollection` file is a way to share one collection, not a full backup: it does not include your other collections,
  recent rolls or settings. To back up everything, copy the data folder (see Data and Upgrades).
- A collection whose rows link to a table in a different collection cannot be exported (TableForge itself never creates
  such links); the refusal names the row.
- Delete Collection cannot be undone.
- Formatting is bold and italic only, on result text only (not table or result-set names). Pasting keeps text only, and
  no export to another tool carries formatting. Recent Rolls show plain text.
- Tables with hundreds of rows take a moment to open on the Review screen; formatting every row of such a table adds a
  little more.
- Image-only or scanned PDFs need OCR first; TableForge reads the text you copy.
- Unusual PDF layouts may need manual cleanup on the Review screen, and TableForge does not find tables in a whole PDF.
- A pasted line starting with a negative number is read as a row only where a row can sit (the first row, or one that
  continues upward from the row before it); elsewhere it stays part of the text above. Check such rows on the Review
  screen.
- Open-ended ranges cannot be exported to Foundry or Tables+ and are not available for `d66`.
- Copy Table Text and Copy Table Text (Spaces) are generic text, not formats for a particular VTT. Importing Copy Table
  Text (Spaces) into Questline has not been verified.
- Copy for Sojour was tested by pasting with Ctrl+V only. It copies rows, not the table's name, dice or links; line
  breaks and tabs inside a result become spaces.
- Foundry export needs the Roll Table Importer module, exports one result set at a time without links, and Foundry does
  not reproduce Clamp. Fantasy Grounds is not supported yet.
- Tables+ export is unchanged since rc23. **Checked in Tables+:** only `d20`, `d66` (`T66`) and unmodified `2d6` tables;
  this is not full Tables+ compatibility. Still untested there: negative modifiers and negative ranges, gaps and
  overlaps, `{2d6}` and `#reroll` in results, a real `1d66`, `d100`, a TableForge export with a single-die modifier, and
  importing a file saved with **Save Tables+ JSON…**. Several dice with a modifier (`2d6+1`) are refused. Tables+ JSON
  has no Clamp setting.
- dddice needs internet and WebView2; connecting an account takes a few browser steps.
- Windows x64 only. Only one copy of TableForge should be open at a time.
- Not code-signed (see Installation).

## Data and Upgrades

Your tables and settings live in `%LOCALAPPDATA%\TableForge` (**Open Data Folder** shows it). Installing a newer version
keeps them; uninstalling TableForge does **not** delete them, and reinstalling finds them again. To back up, close
TableForge and copy that folder.

1.0.0 **does not change the data format** (it stays at version 10) or the `.tfcollection` format, so updating from rc26
needs no conversion and makes no safety copy, and rc26 can still open data that 1.0.0 has used. The Streaming Overlay
keeps its settings in `streaming-overlay.json` and its page in `streaming-overlay.html` in the same folder;
rc26 simply ignores them. Updating from rc25 or earlier converts the data to version 10 exactly as rc26 does, first saving
`tableforge.pre-v10-from-v9.backup.db` (from rc24 or rc25; from rc23 or earlier the copy is named after the version it
came from, for example `tableforge.pre-v10-from-v8.backup.db`); after that, **rc25 and earlier cannot open the data**:
they say it was made by a newer version and change nothing. To go back to rc25, close TableForge and restore that safety
copy as `tableforge.db` (tables, descriptions and rolls added since then will be lost).
